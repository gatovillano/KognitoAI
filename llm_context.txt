# Memoria de Sesión del LLM

## Resumen del Proyecto Kognito AI System:

Kognito AI System es un "exocerebro digital" personalizable y colaborativo que integra IA avanzada, grafos de conocimiento (Cognee + Neo4j), gestión de memoria vectorial (PGVector) y una interfaz multi-plataforma (Telegram Bot, Web App, Next.js Dashboard).

**Características Principales:**
- **Sistema de Conocimiento Híbrido:** Grafos de conocimiento con Neo4j y búsqueda vectorial con PGVector para una búsqueda inteligente y visualización interactiva.
- **IA Avanzada:** Agente de IA conversacional (KAI) con más de 30 herramientas.
- **Gestión de Conocimiento:** Documentos, notas colaborativas, insights proactivos y migración automática.
- **Productividad:** Gestión de agenda, entrada multimodal y colaboración en equipo.
- **Interfaces:** Bot de Telegram, Panel Web, Frontend Web (Next.js) y Neo4j Browser.

**Arquitectura:**
Sistema de microservicios con Backend (FastAPI), Frontend Web (Next.js), Telegram Client, Telegram Panel, Bases de Datos (PostgreSQL + PGVector, Neo4j) y módulos para Grafos de Conocimiento.

**Stack Tecnológico:**
Python 3.11, FastAPI, LangChain, LangGraph, Google Generative AI, Cognee, Neo4j, Next.js 14, React, TypeScript, Docker, Docker Compose, Nginx.

**Configuración:**
Requiere Docker, Docker Compose, 8GB RAM y Google API Key. Se configura mediante variables de entorno en un archivo `.env` y se inicia con `docker-compose up -d`.
## Resumen de `core/llm_manager.py`:

Este módulo es el **corazón de la interacción con los Modelos de Lenguaje Grandes (LLMs)** en Kognito AI. Se encarga de la inicialización, gestión y uso de diferentes LLMs, priorizando Google Generative AI.

**Funcionalidades Clave:**
-   **`RateLimitedChatModel`**: Un wrapper para `BaseChatModel` que introduce un retraso configurable antes de cada llamada a un LLM para evitar exceder los límites de tasa de las APIs.
-   **Inicialización de LLMs (`initialize_llms`)**:
    -   Configura dos instancias globales de LLM: `_main_agent_llm_instance` (para el agente principal, usando `google_main_model_name`) y `_fast_task_llm_instance` (para tareas rápidas, usando `google_summary_model_name`).
    -   Utiliza `ChatGoogleGenerativeAI` y `ChatOpenAI` (aunque la inicialización actual se enfoca en Google).
    -   Aplica el `RateLimitedChatModel` a ambos LLMs.
    -   Maneja errores y fallbacks si un LLM no puede inicializarse.
-   **`get_main_llm()` y `get_fast_llm()`**: Funciones para obtener las instancias de LLM inicializadas.
-   **`get_enhanced_llm_response()`**: La función principal para obtener respuestas del LLM, que puede enriquecerse con contexto del grafo de conocimiento.
    -   Llama a `_get_enhanced_context` para obtener contexto del grafo si `use_knowledge_graph` es `True`.
    -   Construye un prompt enriquecido con este contexto (`_build_enriched_prompt`).
    -   Invoca al LLM principal (`llm.ainvoke(enriched_prompt)`).
    -   Guarda la interacción enriquecida (`_save_enhanced_interaction`).
-   **`_get_enhanced_context()`**: Integra el `EnhancedMemoryManager` y `GraphDB` para obtener contexto del grafo de conocimiento, requiriendo las credenciales de Neo4j.
-   **`_build_enriched_prompt()`**: Construye el prompt final para el LLM, incorporando entidades, relaciones, insights y caminos de razonamiento del grafo de conocimiento.
-   **`_save_enhanced_interaction()`**: Placeholder para guardar las interacciones enriquecidas.
-   **`_get_traditional_response()`**: Función de fallback para obtener una respuesta del LLM sin contexto enriquecido en caso de error.

**Conexión con `config.py`**: Este módulo utiliza intensivamente las `settings` definidas en `core.config` para obtener los nombres de los modelos, API keys, temperaturas y timeouts.

**Importancia**: Este archivo es crucial porque define cómo Kognito AI interactúa con los modelos de IA, cómo gestiona las limitaciones de tasa, y cómo integra el conocimiento del grafo para generar respuestas más ricas y contextualizadas.
## Resumen de `core/agent.py`:

Este módulo es el **núcleo de la inteligencia de Kognito AI**. Se encarga de orquestar la interacción entre el modelo de lenguaje (LLM), las herramientas disponibles y la memoria del usuario para generar respuestas coherentes y útiles. Su arquitectura se basa en el framework **LangGraph**, lo que permite un flujo de ejecución modular y robusto.

**Arquitectura Clave y Componentes:**
1.  **Manejo Manual de Memoria**: A diferencia de las clases de memoria de LangChain, Kognito AI utiliza un ciclo explícito (cargar historial, procesar, guardar historial) para un control más preciso y robusto en un entorno de API.
2.  **Prompt Dinámico Centralizado**: Construye un `SystemMessage` único al inicio de cada ejecución. Este prompt integra:
    *   El perfil del usuario (`get_user_profile`).
    *   Memorias relevantes recuperadas (`get_relevant_memories`).
    *   El prompt de personalidad del asistente (desde `core.prompt_manager`).
    *   Instrucciones sobre el uso de `account_id` y las herramientas.
    *   Prompts específicos del `workspace` si están configurados.
3.  **Inyección Explícita de IDs**: `account_id` y `telegram_id` se pasan al `AgentExecutor` a través del parámetro `config` de LangChain para que las herramientas tengan acceso a la información de la sesión.
4.  **Inicialización de LLMs**: Depende de `core.llm_manager` para cargar las instancias de los modelos de lenguaje al inicio del servidor.
5.  **`AgentState` (LangGraph)**: Define la estructura de datos que fluye a través del grafo del agente. Incluye:
    *   `messages`: Historial de la conversación.
    *   `account_id`, `telegram_id`, `workspace_id`: Identificadores de contexto.
    *   `rag_context`: Contexto RAG explícito seleccionado por el usuario.
    *   `sources`: Fuentes recuperadas para la citación.
6.  **Nodos del Grafo (LangGraph)**:
    *   **`call_model_node`**: El nodo principal donde el LLM es invocado.
        *   Construye el prompt del sistema dinámicamente con perfil de usuario, memorias relevantes (obtenidas de `get_relevant_memories`, incluyendo fuentes para citación) y prompts de workspace.
        *   Prepara el LLM principal (`get_main_llm`) y le vincula las herramientas disponibles (`get_all_langchain_tools`).
        *   Invoca la cadena del LLM en modo streaming y envía fragmentos de la respuesta al frontend a través de WebSockets (`send_personal_message`), lo que mejora la experiencia de usuario.
        *   Almacena las fuentes recuperadas en el estado para su uso posterior.
    *   **`generate_response_node`**: Un nodo final que pasa el estado para que la aplicación frontend lo reciba, actuando como un punto de salida.
7.  **Manejo de Contexto y Memoria Adicional**:
    *   **`summarize_history_in_background`**: Resume mensajes en segundo plano usando un LLM rápido (`get_fast_llm`) y guarda este resumen en la memoria vectorial (`add_memory_to_vector_db`) sin borrar el historial completo, manteniendo el contexto para el LLM y el historial para el frontend.
    *   **`update_thread_title_if_needed`, `force_update_thread_title`, `force_update_all_thread_titles`**: Funciones para generar y actualizar dinámicamente los títulos de los hilos de chat, mejorando la organización de las conversaciones. Incluyen notificaciones WebSocket para el frontend.
    *   **`create_thread_for_account`**: Crea nuevos hilos de chat en la base de datos.

**Conexiones con otros módulos**:
*   `core.tools`: Para obtener las herramientas que el agente puede usar.
*   `core.memory_manager`: Para obtener perfiles de usuario y memorias relevantes.
*   `core.llm_manager`: Para obtener las instancias de los LLMs.
*   `core.prompt_manager`: Para construir el prompt del sistema.
*   `core.database`: Para interactuar con la base de datos (hilos de chat, cuentas, workspaces).
*   `core.websocket_manager`: Para enviar mensajes en tiempo real al frontend.

**Importancia**: `core/agent.py` es fundamental porque integra todos los componentes clave del sistema (LLMs, memoria, herramientas, perfiles de usuario, contextos de workspace) en un flujo de trabajo cohesivo y reactivo, permitiendo a Kognito AI funcionar como un asistente inteligente y contextualizado.

### 27. `utils/ascii_logo.py`
Este módulo contiene el código y los datos para generar y mostrar un **logo ASCII art de Kognito AI con colores** para la consola al inicio del sistema. Incluye funciones para obtener el logo principal, información del sistema híbrido (Qdrant, Cognee, Ollama, pgvector, Neo4j), y mensajes de inicio con la versión, así como opciones para logos simples y mini.
